## Notes

- Revision label is the PDF creation date (2026-03-23; HTTP Last-Modified 2026-03-26 06:08 GMT, unchanged on 2026-11-12). The document states no version number of its own.
- Versions (ADR 0021): 59 operations state a minimum ("UniFi Access Requirement") from 1.20.11 to 4.0.10; the other 48 have only the §1.5 minimum 1.9.1. §13 Change Logs lists V2.2.6, V2.2.10, V3.1.30, V3.2.20, V3.3.10, v3.3.21, v4.0.10 and v4.2.16. Nothing states an upper bound. Corrected 2026-11-12: Phase 0 recorded both ranges as ending at 3.1.30.
- Access 4.2.16 was published three hours before the PDF's Last-Modified time and is its newest change-log entry. This suggests, but the vendor does not state, that the PDF describes 4.2.16 (ADR 0021).
- Port 12445 per API reference §1.2 and §2.6 and the Required Ports Reference (help.ui.com article 218506997, updated 2026-11-06). The "Getting Started with UniFi Access" FAQ (article 17452334269975) lists 12455 for "OpenAPI access". This is treated as a vendor documentation discrepancy: the port stays configurable per console, with default 12445.
- §2.6: "The server certificate is self-generated and untrusted." Consoles therefore need certificate pinning or a custom CA (spec §4.4). §12.1 lets an administrator upload a custom HTTPS certificate.
- Response envelope {code, msg, data}; success only when code == "SUCCESS". HTTP status alone is not success (spec §4.4). Error codes are listed in §2.4.
- §1.5: the API is unavailable after upgrading to UniFi Identity Enterprise (CODE_OTHERS_UID_ADOPTED_NOT_SUPPORTED).
- Every operation declares a vendor permission key (view:* / edit:*), which the token's permission scopes enforce on the console. This is a vendor-side least-privilege layer in addition to this project's policy.
- §11.1 notifications use WebSocket: wss://{consoleHost}:12445/api/v1/developer/devices/notifications with the same bearer token.
- §11.7 describes the inbound webhook delivery contract (console to your endpoint). It is not an outbound operation and is excluded from the inventory. This project exposes no inbound webhook receiver.
- Transcription normalisations: ":param" becomes "{param}"; §8.3 method printed as "PUT\" is read as PUT; §9.4 and §9.5 paths printed without a leading slash were given one (documentedPath keeps the original).
