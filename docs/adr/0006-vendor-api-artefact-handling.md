# 0006. Vendor API artefacts: reference, verify, do not redistribute

- Status: Accepted
- Date: 2026-11-10
- Phase: 0
- Spec references: §4.3, §4.5, §14 (last bullet), §15 (`api-specs/`)

## Context

Spec §4.3 asks for version snapshots "checked in with provenance and revision/checksum,
subject to vendor terms and copyright". Spec §14 forbids "copied proprietary docs beyond
allowed terms". No licence or redistribution terms were found for the developer.ui.com
OpenAPI documents or the Access API reference PDF. Ubiquiti's general Terms of Service
grant only a limited, non-transferable licence to use its services.

## Decision

1. **Do not commit vendor artefacts.** `api-specs/**/vendor/` is gitignored and holds a
   local cache of the verbatim OpenAPI JSON, `llms.txt` index and PDF.
2. **Commit provenance.** `api-specs/<app>/<revision>/provenance.json` records each
   artefact's URL, SHA-256, size and media type. It also records the local base URL,
   forbidden cloud base URLs, authentication facts, notes and unverified assumptions.
3. **Commit a minimal derived inventory.** `operations.json` holds only interoperability
   facts: HTTP method, path template, vendor operationId, first tag, endpoint title,
   documentation link and (Access) permission key. Schemas and prose are not copied. For
   OpenAPI sources it is regenerated by `scripts/reconcile-api-coverage.ts --write`. For
   the Access PDF it is transcribed by hand, with the section and page of each operation in
   `sourceRef`.
4. **Verify, never trust.** `scripts/fetch-api-specs.ts` downloads only from allowlisted
   HTTPS origins (`developer.ui.com`, `assets.identity.ui.com`) with redirects refused, and
   verifies SHA-256 and size. A mismatch is quarantined as `*.mismatch` and fails the run.
5. **Reconcile in CI.** `scripts/reconcile-api-coverage.ts` fails on any unreviewed
   difference between the vendor contract, `operations.json` and the coverage matrix.
   `tests/contract/api-inventory.test.ts` checks the committed files offline in every test
   run.
6. **Adapter schemas** (Phase 2+) are written or generated into adapter packages as
   _our_ runtime validation code. Generation reads the local vendor cache, and the generated
   output is reviewed like any other code. Security metadata is always hand-written
   (spec §4.3).

## Consequences

- Contributors must run `npm run api:fetch-specs` (internet required) before working on
  adapters. The running service never needs vendor documents or internet access (spec
  §2 decision 37).
- If Ubiquiti publishes a permissive licence for these artefacts, a new ADR may allow
  committing snapshots.
- If the vendor silently changes a published artefact at the same URL, it is detected as a
  checksum mismatch and handled as a new revision.

## Re-evaluation triggers

- Vendor licence terms are published or clarified.
- CI needs fully offline reconciliation (an internal artefact mirror would be needed).
